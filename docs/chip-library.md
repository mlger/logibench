# Chip library authoring guide

The library lives in `src/data/chips.ts`; the schema is in
`src/lib/logibench/types.ts`. Every chip is one `ChipDef`. This page explains
each field, who consumes it, and the conventions — read it together with
[CONTRIBUTING.md](../CONTRIBUTING.md#adding-a-chip-to-the-library) (the
process) and [datasheet-sources.md](datasheet-sources.md) (the citations).

## Field reference

```ts
interface ChipDef {
  id: string;              // "7447" — also the palette id and BOM key
  name: string;            // human title, e.g. "BCD to 7-segment decoder/driver (CA, OC)"
  families: Family[];      // which variants the user can place: 'LS' | 'HC' | 'HCT' | ...
  package: 'DIP8' | 'DIP14' | 'DIP16';
  pins: PinDef[];          // index = pin number - 1; EVERY pin, nc included
  power: { vcc: number; gnd: number };  // 14/7 normally — 7490 is 5/10!
  model: ChipModelKind;    // 'gates' | 'decoder' | 'counter' | 'none'
  units?: GateUnit[];      // gates model: one entry per gate
  truthTable?: TruthRow[]; // function-table rows for the reference tab
  glyphs?: Record<number, string>;     // decoder: code -> "abcdefg", '1' = lit
  glyphVerify?: Record<number, boolean>; // rows that are bench-unverified guesses
  electrical: FamilyElectrical;        // family thresholds/currents (see below)
  limits?: { iccMaxmA?: number; ioMaxmA?: number }; // package current budget
  datasheets: DatasheetRef[];          // vendor, doc, rev, url — primary sources
  gotchas: string[];                   // classic mistakes, shown in Inspector
  refOnly?: boolean;                   // pin data only, no sim model yet
}
```

### `pins` — `PinDef`

| Field | Meaning |
|---|---|
| `num` | physical pin number |
| `name` | datasheet name (`Y`, `Q0`, `BI/RBO`, `MR1`…) |
| `dir` | `in` \| `out` \| `io` \| `pwr` \| `gnd` \| `nc` |
| `activeLow` | true for overlined pins (`LT`, `BI`, `MR`, enables…) |
| `output` | `push-pull` (default) \| `open-collector` (7447 outputs) \| `pullup-oc` \| `weak-pullup` |
| `role` | decoder/counter control role: `lt` \| `bi` \| `rbi` \| `le` \| `reset` \| `set9` \| `clock` \| `enable` |

ERC and the simulator read `dir` and `output`; the reference tab renders
`name`, overlines from `activeLow`, and the truth table next to it.

### `units` — the gates simulation model

One entry per logic unit:

```ts
{ fn: 'NAND', inputs: [1, 2, 3, 4, 5, 6, 11, 12], output: 8 }  // the 7430
```

`evalGate` in `sim.ts` applies the function over **any input width**, so
wider/narrower gates need no simulator change. Quad gates are generated by the
`quadGate()` helper; hand-write units whenever the pinout is non-standard.

### `electrical` — `FamilyElectrical`

Per-chip copy of the family numbers (populated by the `TI_LS`/HC presets, then
overridden per datasheet):

`vih` / `vil` (input thresholds, V) · `voh` / `vol` (output levels, V) ·
`ioh` (max source, negative mA) / `iol` (max sink, mA) · `iih` (µA) /
`iil` (negative mA) · `floatReads: 0 | 1 | 'X'` (LS floats HIGH, HC floats X —
this is what makes the `floating-input` rule's severity family-dependent) ·
`fanout` (in LS loads).

The `ls-to-hc` rule compares driving `voh` against receiving `vih`
(2.7 V < 3.15 V → warning; HCT's TTL thresholds are exempt).

### `model` kinds

- `gates` — driven by `units[]`;
- `decoder` — driven by `truthTable` + `glyphs` (7447/7448/4511);
- `counter` — bespoke edge-triggered model in `sim.ts` (7490);
- `none` — `refOnly` reference data, no simulation.

## Worked example: the 7430

Single 8-input NAND, DIP14 — deliberately *not* the quad layout. Verified
against TI SDLS099 (scanned TOP VIEW) and cross-checked against the Logisim
TTL library (both agree):

- inputs A–F = pins 1–6, G = 11, H = 12; output Y = pin 8;
- NC = 9, 10, 13 (present in `pins[]` as `dir: 'nc'`);
- power 14/7; unit: `{ fn: 'NAND', inputs: [1,2,3,4,5,6,11,12], output: 8 }`.

Because `evalGate` is width-agnostic and the footprint comes from
`chipPackage('7430') → 'DIP14'`, the only code touched was `chips.ts`,
`geometry.ts`'s `known` table, and `docs/datasheet-sources.md`.

## Consumers (who reads what)

| Consumer | Reads |
|---|---|
| `geometry.ts` | `package` (via `chipPackage` map), `pins.length` (`pinCount`) |
| `netlist.ts` | nothing — it only knows holes and part pin counts |
| `sim.ts` | `units`, `model`, `electrical.floatReads`, `truthTable`/`glyphs` (decoders), `refOnly` |
| `erc.ts` | `power`, `pins[].dir`/`output`, `electrical` (LS→HC), `limits.iccMaxmA`, `name` for messages |
| `ReferenceTab` | `pins`, `truthTable`, `glyphs` + `glyphVerify`, `datasheets`, `gotchas`, families |
| `bom.ts` / Inventory | `id`, `families` for substitution checks |
